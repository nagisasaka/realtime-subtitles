# 履歴の自然さ改善：7案の比較（2026-10-09）

現時点では、**最新が上の表示順を分割モデルへ伝え、理由とその帰結を同じ段落に保つ案**をmainの履歴分割指示へ反映した。開発8窓で1勝・7同等、保留4窓で全て同等。改善は限定的であり、全般的な翻訳品質の向上とは主張しない。

評価モデルの提示順反転・両案の独立再生成でも、改善した窓は候補優位だった。逐次更新1ケースでも改善を確認した。ただし2ケース目はAPIクレジット不足で途中停止し、追加確認が残っている。常用Windowsアプリは再起動せず、独立した検証環境で確認した。

## 調査から試行へ

参照文献・着想・事前の採否基準は[比較計画](history-naturalness-plan.md)に記載した。

文法構造と分割の関係を扱う[字幕読解の研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7901653/)から、短さの一律制限より意味上のつながりを重視した。[文脈と指示・語彙的一貫性の研究](https://aclanthology.org/P19-1116/)から、日本語表現を変える複数案も分けて試した。これらの研究結果がそのまま本アプリに成立するとは仮定していない。

追加案では、現在の画面は最新段落が上に来るため、後ろの段落が「そのため」から始まると、読者が理由を下へ探しに戻る点を明示した。文法上独立していても、直前の主張に依存する結論・説明は同じ英日ペアにする。人物名の補正や本文の書き換えは行わない。

## 条件

- 開始時main: `20808b1`。評価環境commit: `6e87ad5`。
- データ: Earnings22のQudian (`4474955`) / Arqit (`4475604`)。保存済みAgent STT出力を使用。開発8窓・保留4窓、区間長の合計187.32秒。追加の逐次更新・再生成は別枠。同じ音声を再度ASRへ送ってはいない。
- 出典: [revdotcom/speech-datasets, Earnings22](https://github.com/revdotcom/speech-datasets/tree/c05ab6fd8b4b627d123c922a22a39e993dd37635/earnings22)、CC BY-SA 4.0。元のsource manifestとSHA-256を固定。
- 生成: `gpt-6-luna` / reasoning `none`、現行の英文分割→IDごと一括翻訳。
- 評価: `gpt-6-astra` / reasoning `low`。匿名A/B、自然さ・理解しやすさ（各1〜5）、選好、内部境界、過剰結合、重大な意味変更、英日対応を別記。入力や出力中の命令文はデータ扱い。
- [OpenAIの評価ガイド](https://developers.openai.com/api/docs/guides/evaluation-best-practices)に従い、順序の反転と具体的な根拠を確認した。LLMによる人間感覚の代理評価であり、人間の被験者実験ではない。
- 原文・contextが開発と保留に跨らないことを検査。今回の案選定に未使用の保留群であり、過去の全試行から未使用という意味ではない。
- API同時要求2、1イテレーション既定300秒・上限480秒、全試行上限240。SDK自動retryなし。通常の翻訳Validatorは従来通り最大1 retry。

## 比較結果

各行は同じ開発8窓。勝敗は現行に対する読みやすさの選好であり、重大な意味変更があれば勝数にかかわらず棄却する。

| 案 | 勝 / 同等 / 負 | 自然さ差の平均 | 判断 |
|---|---:|---:|---|
| 1 意味上のまとまりを優先する分割 | 0 / 8 / 0 | 0.000 | 全出力が同じ。指示を増やす根拠なし |
| 2 日本語の語順・述語を自然化 | 3 / 3 / 2 | +0.125 | 未完の貸出残高に「同様です」と追加。棄却 |
| 3 冗長表現を簡潔化 | 3 / 4 / 1 | +0.125 | 法令名やcontextの持ち込みへの指摘あり。棄却 |
| 4 指示語・主語の対応を明確化 | 3 / 5 / 0 | +0.250 | 原文のourから「当行」と補った例。修正して再試行 |
| 5 用語・数値表記を統一 | 1 / 6 / 1 | −0.125 | 一貫した改善なし |
| 6 案4＋組織種別・欠落情報の推測禁止 | 2 / 3 / 3 | −0.125 | 当行は解消したが、別の表現で劣化・補完。採用せず |
| 7 最新が上の履歴に合わせて依存文を結合 | 1 / 7 / 0 | +0.125 | 採用。新たな重大誤訳・対応崩れは確認されず |

最初の5案は出力取得前に固定した。6・7は開発結果を見て追加した案で、別JSONに親manifestのhashと変更理由を保存した。元の5案・採点基準は変更していない。7は英文分割指示だけを変え、日本語翻訳指示は現行のまま。

7案すべて8窓の生成・判定が揃った。構造失敗、ローカルValidatorによるretryは0。原文・prompt・schema・modelが同一の要求はcacheを共有するため、56比較を独立した56標本とは扱わない。1案目と7案目の一部には同一出力・同一判定の再利用がある。

## 具体例

### 分割の改善：Qudian 58.68–83.76秒

該当する原文（文字・順序は変更しない）:

> Forward looking statements involve inherent risks and uncertainties. As such, the company's results may be materially different from the views expressed today.

現行は「リスクがある」と「そのため結果が異なる可能性がある」を別ペアに分ける。最新が上の画面では、結論が先に現れ、理由はその下に来る。

新指示は両文を1ペアに保つ。取得した訳は:

> 将来予想に関する記述には、本質的にリスクと不確実性が伴います。そのため、当社の実績は、本日述べる見解と大きく異なる可能性があります。

窓全体は4段落→3段落。内部の英文順は通常の読順、段落間は従来通り最新が上。単純な最小語数や一律結合ではない。ほかの7開発窓・4保留窓は同じ分割・訳文を維持した。

### 不採用例：Qudian 174.56–183.20秒

原文の末尾は `And our own balance sheet loan. Balance.` で終わる。案2は「当社の貸借対照表上の貸出残高も同様です」として、直前の34億人民元との関係を追加した。これは自然さの改善として採用できない。

案4の「当行」も、原文・contextに銀行という特定がないため採用しなかった。judgeの重大エラー欄が空でも、根拠のある懸念は別途レビューした。案6では「当行」はなくなったが、別区間の未完の公開先に「こちら」を補ったため、そのまま採用しなかった。

## 遅延・負荷

以下は保存済み文字起こしに対する分割API＋翻訳API待ち時間の合計。queue待ち、音声認識、ライブ字幕までの時間ではない。共通API要求のcacheには元の実測時間を使用している。

| 条件 | p50 | p95 |
|---|---:|---:|
| 現行・開発8窓 | 4.33秒 | 5.71秒 |
| 採用案・同じ8窓 | 3.77秒 | 4.48秒 |
| 現行・独立再生成2窓 | 7.73秒 | 8.34秒 |
| 採用案・独立再生成2窓 | 6.22秒 | 6.24秒 |

呼出回数は従来と同じ2段階。追加モデル・待機タイマー・文法規則は導入していない。今回の小標本・cache混在から「高速化した」とは結論しない。

各案の開発イテレーションは19.43〜60.48秒で終了（準備・コード編集・人による確認時間を除く）。短い窓とcacheを使っているため、音声全体のライブ再生時間とは比較できない。

2026-10-09の停止時点で167試行を計上。Luna 110（成功104・429が6）、Astra 57（全成功）。成功応答のusage合計はLuna入力91,722 / 出力7,323 token、Astra入力129,743 / 出力33,556 token。金額はこの報告では推計しない。

## 残課題と適用状況

追加試行の429は、診断1回で `credit_balance_exhausted` と確認した。残高不足が分かった後はAPI送信を停止している。未完のr17逐次比較は、補充後に独立した`--nonce recovery2`で実行し、元の失敗記録は残す。

また、従来からある窓端の補完（例: `To ...` に「ようこそ」、`non IFRS`に「指標」）や、保留群の`public shareholders`を「個人株主」とする訳は、今回の案では解消していない。対応を含めた完全な忠実性の保証はできない。英語ASRの誤りも訂正していない。

評価対象は決算説明会2本の短い抜粋であり、展示会・雑談・広範な技術講演への一般化は未確認。採用したのは確認できた小さな改善であり、再翻訳全般が自然になったと断言しない。

mainのソースとWindows検証用コピーに実装済み。常用のWindowsコピーと稼働中プロセスは、この評価中には入れ替えていない。残る逐次比較と適用確認後に常用側へ反映する。
